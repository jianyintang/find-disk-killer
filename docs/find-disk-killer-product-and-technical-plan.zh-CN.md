# FindDiskKiller macOS 磁盘 I/O 监控软件方案

> 文档状态：已签发（2026-07-23）<br>
> 目标平台：macOS 14 及以上，Apple Silicon 与 Intel 均纳入持续构建和核心冒烟测试<br>
> 产品形态：菜单栏常驻工具 + 原生桌面主窗口 + 可选 Endpoint Security 系统扩展<br>
> 核心承诺：以应用为中心，让用户快速看见“哪个应用正在持续使用磁盘、CPU 或网络，以及这种行为是否异常”，并在证据允许时继续回答它关联了哪个卷和文件；始终明确展示数据精度与权限状态。

## 1. 产品定义

FindDiskKiller 是一款面向开发者、创作者、运维人员和高级 Mac 用户的本地磁盘 I/O 诊断工具。它解决三个连续问题：

1. 当前是否存在异常磁盘读写？
2. 压力来自哪一块物理磁盘或逻辑卷？
3. 哪些进程、应用和文件路径与这次写入有关？

产品不是 Activity Monitor 的替代品，也不追求堆叠系统指标。它把一次典型排查压缩为三步：从菜单栏感知异常，在“现在”中定位最活跃的应用，再把同一应用的磁盘 I/O、CPU、网络和文件证据放在一条时间线上解释。

### 1.1 核心用户任务

- 查明风扇升速、卡顿或电量异常时，后台是谁在持续写盘。
- 判断大型构建、同步、下载或媒体任务主要影响哪块磁盘。
- 发现某个进程的突发写入，并查看它涉及的文件或目录。
- 在一段时间内记录证据，导出给开发或运维人员分析。

### 1.2 产品原则

- **先结论，后指标**：默认展示状态、主要压力源和异常原因；专业指标在下钻页中完整提供。
- **精度诚实**：物理设备吞吐、进程累计 I/O、文件写入事件来自不同内核口径，不伪装成可严格相加的数据。
- **权限渐进**：未授权时仍能使用基础监控；需要进程到文件的归因时，再解释收益并请求权限。
- **安静常驻**：不发送系统通知、不自动弹出窗口；异常状态仅在用户主动打开的菜单栏面板和主窗口中呈现。
- **本地优先**：采集、聚合、历史记录和导出全部在本机完成，默认不上传遥测。
- **原生语言体验**：应用内可即时切换 10 种语言，动态句子、图表辅助信息、权限说明与数字格式使用同一语言环境，不以逐词直译代替母语表达。

## 2. macOS 能力边界与关键决策

### 2.1 三类数据及其真实含义

| 数据 | 推荐来源 | 可回答的问题 | 主要限制 |
| --- | --- | --- | --- |
| 设备累计读写字节、操作数 | IOKit / IORegistry 中 canonical `IOBlockStorageDriver` 统计节点，按固定间隔取差值 | 哪块物理设备吞吐最高、趋势如何 | 驱动字段不完全一致；延迟/总耗时仅按能力矩阵启用，不承诺通用的 0–100% 忙碌度 |
| 进程累计磁盘读写字节 | `proc_pid_rusage` 等公开进程统计接口，按进程生命周期取差值 | 哪些可见进程在产生最多磁盘 I/O | 基础代理受同 UID 权限限制；短命进程可能被漏掉；其口径与物理落盘字节不完全相同 |
| 系统与进程 CPU 时间 | host CPU ticks 与 `proc_pid_rusage` 的 user/system time，按累计值取差；进程时间先用 `mach_timebase_info` 从 Mach absolute-time ticks 换算为纳秒 | 整机 CPU 压力、哪个应用在持续占用 CPU、区间平均与峰值 | 整机显示 0–100%；应用采用 Activity Monitor 口径，一个逻辑核满载为 100%，多核应用可超过 100%；Apple Silicon 不得把 absolute-time ticks 直接当作纳秒 |
| 系统与进程网络字节 | 非 loopback 的物理外部接口按 interface index 分别取累计差值后汇总；应用使用 `/usr/bin/nettop` 每进程汇总并按 PID 生命周期取差 | 网络何时持续活跃、哪个应用正在收发数据、区间趋势 | 物理接口视图不重复计入 VPN/隧道层；`nettop` 属于系统工具但输出仍需做版本兼容测试，缺失时明确显示不可用 |
| 进程与文件系统活动事件 | Endpoint Security 的必要通知事件 | 谁对哪个文件产生了何种活动、该对象属于哪个卷 | 需要 entitlement、系统扩展批准及完全磁盘访问；事件不提供可靠写入字节数，各事件的证据强度不同 |

ES 事件在数据模型中严格分类：`NOTIFY_WRITE` 表示确认观察到写入调用；`CLOSE.modified == true` 表示关闭时确认曾被文件系统调用修改；`was_mapped_writable` 仅表示可能发生可写映射，且只在 `message.version >= 6` 时读取；CREATE/RENAME 只属于元数据活动，不计入确认写入。任何一类事件都不能推导写入字节数或偏移。

### 2.2 归因结论必须展示证据，而不是伪造精度

界面不得直接声称“进程 A 向磁盘 B 精确写入 1.2 GB”。建议显示以下三种证据：

- **设备实际写入**：来自设备计数器，可作为磁盘层的真实吞吐。
- **进程磁盘写入**：来自进程资源统计，代表该进程自身的累计 I/O 变化。
- **关联写入活动**：Endpoint Security 证明该进程在采样窗口内写过属于该卷的路径，但写入字节为估算或未知。

当需要给出“主要相关进程”排序时，采用证据状态，而不是容易被理解为数值准确度的“高/中/低置信度”：

- **已观察到文件活动**：ES 在当前窗口内观察到该进程写过属于目标卷的路径；这仍不代表其贡献了设备计数器中的某个字节数。
- **时间上相关**：进程 I/O 增量与设备写入同时出现，但没有足够的单卷路径证据。
- **证据不完整**：路径无法映射、短命进程统计缺失、权限变化或事件队列发生丢弃。

列表默认按证据强度、最后活动时间和进程自身 I/O 排序，并提供“依据”弹层，写明来源、观察窗口和估算器版本。允许以进程实测写入为总额、按文件活动启发式估算卷关联量，但绝不与设备物理字节配平，也不把事件数本身展示成写入字节；达不到门槛时整体降级为“字节不可估算”。

### 2.3 明确不用作正式采集链路的方案

- `fs_usage`、DTrace、kdebug 等适合内部验证，不作为生产依赖：权限高、输出格式不稳定，且可能受 SIP 和系统版本影响。
- FSEvents 只能证明目录树发生变化，不能可靠给出写入进程，不用于进程归因。
- 不开发内核扩展。现代 macOS 应采用系统扩展和公开 API。
- 不承诺所有设备的温度、SMART、精确队列深度、通用忙碌度和精确单次写入延迟；仅在阶段 0 的驱动能力矩阵证明字段语义后展示。

### 2.4 分发前置条件与双发布路径

完整模式建议通过 Developer ID 签名、公证后的站外安装包分发，而不是以 Mac App Store 为首要渠道。项目第一阶段即申请 `com.apple.developer.endpoint-security.client` entitlement，并用真实签名验证授权链路。

版本命名统一为：

- **基础版 GA**：提供设备真实吞吐、卷拓扑，以及当前权限可见的进程自身 I/O；不提供进程到文件/卷的归因。阶段 1 与通用发布工程完成后可独立发布。
- **完整模式 GA**：在基础版之上提供 ES 文件活动证据；必须等待 entitlement 获批并通过阶段 2 门禁。

entitlement 已获批时进入完整模式 RC；仍在等待时可以发布基础版 GA，完整模式入口显示“能力准备中”且不诱导授权；被拒绝时从当前版本宣传和界面中移除完整模式承诺，重新评估产品定位。任何版本都不得宣传“精确查看某进程向某磁盘写入的字节数”。

## 3. 产品体验方案

### 3.1 信息架构

主窗口采用 macOS 原生侧边栏，保持稳定的工作区结构：

1. **总览**：当前压力、读写趋势、主要相关进程、最近异常。
2. **磁盘**：物理设备与逻辑卷的层级列表；选择设备后查看吞吐、活动进程和挂载关系。
3. **进程**：按应用聚合，可展开辅助进程；查看读写趋势、关联卷/存储集合和路径。
4. **活动**：可筛选、可暂停的写入事件时间线，支持进程、卷、路径和事件类型过滤。
5. **设置**：使用标准 macOS Settings scene（`⌘,`），包含采样、保留、隐私、排除项、扩展状态和诊断；侧边栏不重复放置设置入口。

默认窗口建议为 `1180 × 760 pt`，最小窗口为 `920 × 620 pt`。侧边栏约 `220 pt`，详情区使用一致的双栏或单栏布局，不在卡片中继续嵌套卡片；窄窗口下顶部指标自动切换为两行，不截断下载或上传数值。

主窗口有唯一的全局时间上下文：`实时`会持续向前滚动，`历史`会冻结开始/结束时间与图表选区。跨总览、磁盘、进程和活动页面下钻时保留时间范围与筛选；从异常状态进入时打开对应历史区间，并始终显示“返回实时”。睡眠、停止采集、扩展断开和事件丢弃在曲线上绘制为不可插值的缺口及原因标记。

### 3.2 菜单栏体验

菜单栏图标是最短入口，而不是缩小版仪表盘：

- 图标旁可选显示当前总写入速率，例如 `42 MB/s`；空间不足时只保留图标。
- 单击弹层包含当前读写速率、当前写入/读取速率最高的磁盘、首要相关进程和最近 60 秒微型趋势。
- 提供“打开 FindDiskKiller”“开始诊断记录”两个清晰操作；退出操作置于菜单底部，文案为“退出并停止采集”。
- 正常状态不加徽标；持续超阈值时使用琥珀色实心圆徽标，故障使用红色三角叹号。形状、菜单文字与 VoiceOver 标签同时表达状态，不只依赖颜色。
- 用户可分别选择显示读、写、总 I/O 或仅图标，避免菜单栏被长数字挤压。

全产品只使用三种操作语义：

- **暂停实时跟随**：仅冻结当前 UI，采集和历史仍继续。
- **停止采集**：停止所有新样本并在历史中形成明确缺口，需要二次确认。
- **诊断记录**：在用户明确同意后，为本次有时限、有容量上限的会话额外保存完整路径；它不是普通持续历史的开关。

### 3.3 总览页

首屏按扫描顺序组织，不使用营销式大标题：

- 顶部紧凑状态条：`正常 / 写入偏高 / 数据不完整`、当前监控时长、权限状态和“停止采集”菜单；视图冻结使用图表工具栏中的“暂停实时跟随”。基础模式缺少可选扩展不是“数据不完整”，只有用户已启用的能力意外下降才提示异常。
- 实时摘要：CPU、磁盘、网络下载和网络上传均按最近 5 秒实际采样时长计算，不使用整段曲线平均；下载与上传始终分别显示。设备行也采用同一最近 5 秒口径。
- 主趋势图：读、写两条直线折线，可切换 `1 分钟 / 15 分钟 / 1 小时`；鼠标悬停时吸附最近样本，以紧凑且区别于背景的小卡片展示精确时间与全部可见序列数值，卡片根据选中点位置左右避让。
- 磁盘列表：以 `Macintosh HD`、`JianDisk` 等挂载卷名为第一标识，通过 APFS physical store 映射展示对应物理设备的读取、写入；共享存储明确标注“与其他卷共享设备”，不把设备吞吐伪装为卷独占吞吐。缺失指标显示 `吞吐暂不可用`，不显示虚假的零。
- 主要相关进程：应用图标、名称、最近 5 秒 CPU、进程自身写入总量、平均、峰值、下载平均和上传平均；默认按最近 5 秒 CPU 排序，每列表头均可升降序切换。基础模式使用用户可理解的“全盘 I/O 合计”，并明确提示当前无法区分写入哪块盘，不再使用“待归因”等实现术语。
- 最近异常：只展示已触发且有诊断价值的事件，支持直接进入对应时间范围。

空闲时用“当前无显著磁盘活动”替代空图表提示；数据采集中使用稳定尺寸的骨架占位，避免界面跳动。

### 3.4 时间段写入查询：核心工作流

用户无需理解采集口径即可完成查询：在主图拖选一段时间，或用时间选择器输入起止时间，结果区立即切换为“这段时间谁在向哪些磁盘写”。默认提供 `最近 5 分钟 / 1 小时 / 24 小时 / 自定义`，异常状态入口也进入同一结果页。

首屏默认按“应用/产品 + 目标卷”聚合，CLI 多次重启不会产生大量同名行；展开后才显示进程会话/PID。应用的每个采样桶先汇总子进程，再计算区间总量与峰值。物理设备只作为次级拓扑；只有卷到设备经验证为一对一时才显示“关联物理设备”，多对多时显示“存储集合”，不把同一估算量复制到多个设备。表格固定展示：

| 列 | 用户看到的含义 |
| --- | --- |
| 应用 | 图标、产品名、必要时展开到进程/PID |
| 目标卷 | 用户卷名为主；一对一时显示关联物理设备，多对多显示存储集合，网络卷显示“无本地物理吞吐” |
| 关联写入（估算） | `约 2.4 GB`；这是从进程实测写入中按文件活动关联的估算值，不伪装成物理落盘精确值 |
| 平均（估算） | 关联写入估算 ÷ 完整选中时长，包含空闲时段，例如 `约 6.8 MB/s` |
| 峰值（估算） | 最高采样区间平均速率，例如 `约 84 MB/s · 2 秒粒度`；只有连续 1 秒采样时才标为 1 秒峰值 |
| 依据 | `单目标关联 / 多目标事件权重估算 / 字节不可估算`，点击查看文件活动证据、窗口、模型未分配量和估算器版本 |

表格上方用一句可行动摘要回答问题，例如：“过去 15 分钟持续写入偏高；观察到 Claude Code 对 Macintosh HD 中的文件进行写入，关联写入估算约 8.2 GB。”点击任一行进入同一时间段的进程详情与活跃路径。右侧检查器同时展示“进程总写入（实测）”“已关联到卷（估算）”“模型未分配量”，三者关系一眼可核对；所有卷关联值之和不得超过进程总写入。

默认按关联写入估算排序，也可切换估算平均、估算峰值或持续时长。每个值保留真实采样起止时间，不插值；历史聚合桶额外保存子桶最大速率、当时采样粒度和证据状态。界面分别显示“采集完整度”和“分卷估算覆盖率”：无法跨越的 rusage 缺口会让完整区间三项统一显示“字节不可估算”，可切换查看明确标为“仅已观察部分”的数据；采集完整时，分卷估算覆盖率低于 95% 也统一降级。平均始终以完整选择时长为分母，详情可另看“有效采样平均”，两者不得在同一列静默切换。

### 3.5 持续异常与 AI Agent 感知

FindDiskKiller 将“持续读写”视为一级状态，而不是只提示瞬间尖峰：

- 设备层分别检测持续读取和持续写入，结合绝对阈值与设备过去 7 个同类时段的本地基线；持续时间、累计量和当前速率同时显示。
- 进程层展示最近 1 小时/24 小时累计写入、连续活跃时长和相对基线偏离，帮助识别 AI Agent 的索引、缓存、日志与工作区扫描。
- 持续读取异常同样可定位到物理设备，并列出全系统/当前用户的进程读取候选；由于 ES 没有等价的文件 READ 通知，候选必须标记“进程总读取，未按该磁盘归属”，不冒充逐磁盘读取归因。
- 菜单栏摘要明确区分“Claude Code 进程自身持续写入 12 分钟”和“磁盘持续写入 12 分钟 · Claude Code 仅时间相关”，不省略证据关系；点击直接冻结到异常开始至当前的时间段查询。
- 提供内置“AI 开发工具”视图与异常解释，但不因为进程名称属于 AI 工具就默认判定异常；异常只由可验证的持续时间、量级和用户基线触发。

基线使用独立脱敏摘要库，键为 `主体类型（应用/设备）+ 稳定主体身份 + 读/写方向 + 同类时段`，值为分位数、MAD 与样本计数；不含路径，保留 35 天以覆盖至少 7 个同类时段。应用身份使用签名身份与产品版本；设备身份使用经验证的硬件指纹，无法跨重启确认是同一设备时不得继承旧基线，并回到“学习中”。状态分为 `学习中 / 基线可用 / 数据不足`：新装或身份版本变化时使用第 5.1 节的用户可见绝对阈值；MAD 为零时应用最小噪声地板。基线可用后的持续异常默认进入条件为超过动态阈值 60 秒，退出条件为低于阈值 30 秒，允许最多 5 秒短暂空闲而不中断连续时长。睡眠、权限缺口和采集停止不进入基线。

应用图标采用本地优先的回退链：`NSRunningApplication/NSWorkspace` 获取已安装 `.app` 的真实图标 → 代码签名身份匹配内置品牌注册表 → 通用终端或进程图标。只有 signing ID + Team ID 或 bundle ID 精确命中，或可验证父进程链命中已签名宿主时，才显示品牌图标并聚合 CLI 子进程。仅可执行名为 `codex`、`claude` 等时使用通用图标并标记“可能关联”，不得直接品牌化；所有聚合均允许展开原始进程核验。

品牌回退资产可从 [glincker/thesvg](https://github.com/glincker/thesvg) 按固定 commit `9d06a7e32a6403de34378a64fc000fe75da43518` 在构建时选择性 vendoring，不在运行时访问 CDN。必须逐图标读取 registry 的 license：例如该版本的 `claude-code` 与 `codex-openai` 标记为 MIT，而 `codex` 标记为 `brand-use`；仓库代码的 MIT 许可不能替代单个品牌资产许可。发布前保留来源、commit、许可与商标审核记录，存在不明确授权时退回本地应用图标或通用图标。

### 3.6 磁盘详情

物理设备与卷必须在视觉上区分：物理设备为顶层行，APFS 容器和卷缩进呈现。详情页包含：

- 设备身份：用户友好名称、连接类型、容量、BSD 标识与挂载点。
- 实时图表：吞吐、操作数；忙碌度或平均耗时仅在设备支持时出现。
- 相关进程：以“已观察到文件活动 / 时间上相关 / 证据不完整”筛选，点击后联动同一时间范围。
- 活跃路径：默认将用户目录显示为 `~/…`，敏感路径可在设置中进一步遮蔽。
- 卷映射说明：APFS 多卷共享同一物理存储时，明确提示设备吞吐是共享总量。

### 3.7 进程详情

- 使用签名身份、bundle identifier、可执行路径和启动时间区分同名进程。
- 多个 helper 默认聚合到宿主应用，可展开到单独 PID。
- 展示所选时间段的进程总写入、分卷关联写入估算、模型未分配量、估算区间平均、带实际粒度的估算峰值、趋势、最近活跃路径和事件时间线。

### 3.8 活动时间线

时间线面向诊断而非日志倾倒：

- 默认按 `应用 + 路径 + 1 秒窗口`合并事件，显示事件数与最后活动时间。
- 可切换到原始事件视图，但需提示其数据量和性能影响。
- 顶部提供搜索、卷筛选、应用筛选、写入/创建/重命名筛选和实时跟随开关。

- 导出前展示字段预览，并让用户选择是否包含完整路径。

### 3.9 权限与首次启动

首次启动主动呈现权限中心，但仍按能力依赖逐步申请，避免让缺权限静默变成功能缺失。推荐流程：

1. 窗口出现后立即启动无需额外授权的设备、应用 I/O、CPU 与网络采样，同时自动打开一次权限中心。
2. 权限中心逐项显示“正在工作 / 需要授权 / 等待批准 / 已授权 / 被拒绝”，每个未完成项只有一个明确下一步。
3. 当前构建没有可激活扩展时只显示“能力准备中”，不请求 FDA；正式签名版先通过 `OSSystemExtensionRequest` 主动发起系统扩展安装与批准，只有扩展激活且 `es_new_client` 返回 `ERR_NOT_PERMITTED` 时才提供“打开完全磁盘访问”主按钮。
4. 返回应用后自动复检状态；成功即继续，仅在系统明确要求时提示重新登录或重启。
5. 用户选择稍后时基础监控继续完整工作，不重复弹窗；进入需要完整归因的页面时再次提供上下文相关的授权入口。

权限引导采用逐步状态机，分别跟踪 Agent 后台许可、系统扩展未安装/待批准/已激活、完全磁盘访问，以及 ES client 已连接/订阅失败。`OSSystemExtensionRequest` 只判断扩展生命周期；FDA 由扩展内部 `es_new_client` 的结果判断，并分别处理 `ERR_NOT_PERMITTED`、`ERR_NOT_ENTITLED`、`ERR_NOT_PRIVILEGED` 和 `ERR_TOO_MANY_CLIENTS` 后经 XPC 回报。每一步均有 `未开始 / 等待批准 / 已授权 / 被拒绝 / 已撤销 / 异常` 状态和唯一下一步。返回应用后采用有限退避复检或重建 client；若系统要求重新登录或重启，按实际结果提示。取消或撤销后自动降级并保留设备监控，不循环弹窗。

## 4. 技术架构

### 4.1 组件划分

```text
FindDiskKiller.app（SwiftUI）
  ├─ 总览、详情、设置、历史与导出
  ├─ Swift Charts（降采样后的展示数据）
  └─ 与常驻代理的 XPC 客户端

FindDiskKillerAgent（`SMAppService.agent(plistName:)` 注册的每用户 LaunchAgent）
  ├─ IOKit 设备采样与 Disk Arbitration 映射
  ├─ 当前登录用户可见的进程资源统计轮询与身份缓存
  ├─ 时间窗口聚合、规则引擎、SQLite 持久化
  └─ 与系统扩展、主应用之间的 XPC 边界

FindDiskKillerEndpointExtension（Endpoint Security 系统扩展，可选）
  ├─ 仅订阅归因所需的通知事件
  ├─ 将 audit token、进程身份、st_dev、路径状态和事件类型转为最小事件信封
  ├─ 完整模式下采样系统级进程 rusage，并按用户隔离后输出聚合结果
  ├─ 有界队列、背压、丢弃计数和自有进程静默规则
  └─ 不执行策略拦截，不订阅 AUTH 事件

FindDiskKillerCore（共享 Swift Package）
  ├─ 数据模型、单位格式、时间桶、关联估算与证据状态计算
  ├─ XPC Codable DTO 与版本协商
  └─ 纯逻辑测试夹具
```

系统扩展在 `Info.plist` 中配置 `NSEndpointSecurityMachServiceName` 并作为 XPC listener，Agent 作为 client；App↔Agent 与 Agent↔Extension 使用两个独立协议和信任边界。常驻代理负责跨 UI 生命周期保存数据；退出主窗口不会中断监控。

### 4.2 采集与数据流

1. 代理每秒读取每个物理存储唯一 canonical 统计节点的累计计数器，使用单调时钟计算差值，检测回绕、设备移除和睡眠唤醒，避免重复统计 IORegistry 多层节点。
2. 基础模式由 Agent 以 1 秒周期扫描同 UID 可见进程。完整模式切换为 root 系统扩展作为所有进程 rusage 的唯一权威来源，Agent 停止进程采样，不合并或相加两路差值。空闲连续 60 秒后退到 2 秒周期，活动连续 5 秒后恢复 1 秒；CPU 超预算时不提升频率。
3. 系统扩展异步接收事件，在 ES message 有效期内复制 `audit token`、进程身份、`es_file_t.stat.st_dev`、路径及 `path_truncated`，随后立即释放消息。
4. 使用采样时刻的 `st_dev/fsid -> 挂载点/volume UUID` 快照映射卷；路径只用于展示，不在排队后依赖 `statfs(path)`。路径截断但 `st_dev` 有效时仍映射卷并标“路径不完整”；仅设备映射失败时标“未知卷”。Disk Arbitration 提供挂载描述，IOKit/IOMedia 图提供块设备关系。
5. 聚合器按单调时间归并设备样本、进程差值和文件事件，生成带真实起止与实际粒度的样本桶及证据状态，不修改原始口径。
6. UI 通过 XPC 订阅最多 2 Hz 的快照；图表根据像素宽度做 min/max 或 LTTB 类降采样，避免把每个原始点交给 SwiftUI。

### 4.2.1 进程到卷的字节估算

为了支持“某段时间内某进程写了哪个卷多少数据”，每个进程样本保留真实的单调时钟起止时间，按实际 1 秒或 2 秒粒度形成 provisional 桶；等待最多 5 秒吸收延迟到达的活动证据后冻结。历史 10/60 秒聚合桶保留子桶最大速率、对应时间、实际粒度、定稿状态与估算器版本。每个桶包含以下互不混淆的量：

- `processWrittenBytes`：`proc_pid_rusage` 的进程累计写入差值，是进程层实测值。
- `deviceWrittenBytes`：IOKit 设备计数器差值，是物理设备层实测值。
- `associatedWrittenBytes[volume]`：把进程实测值依据 ES 确认写入活动关联到目标卷的估算值。
- `modelUnassignedBytes`：模型未分配的进程实测写入量，不称为事实性的“真实未归属字节”。

估算规则必须确定、可测试并可解释：

1. 从 WRITE 与 `CLOSE.modified` 建立归因窗口内的目标卷集合。`path_truncated` 但 `st_dev` 有效时仍可映射卷，只标记路径不完整；CREATE/RENAME 和“可能的可写映射”不参与分配。
2. 若窗口存在 ES 序号缺口、本地丢弃、无法映射的确认写入目标或非分配类可写映射证据，则整个桶不输出分卷数值：`modelUnassignedBytes = processWrittenBytes`，UI 三项均显示“字节不可估算”。
3. 否则设进程实测写入为 `W`，卷 `v` 的 WRITE 次数为 `writeCount(v)`；若某卷只有 `CLOSE.modified` 而无 WRITE，则令其 `score(v) = 1`，其余为 `score(v) = max(writeCount(v), 1)`。单目标时 `A(v)=W`；多目标时 `A(v)=W × score(v) / Σscore`。`modelUnassignedBytes = W - ΣA(v)`，仅用于处理舍入。这个公式是事件数量启发式，不是字节覆盖率。
4. `proc_pidfdinfo` offset 首版不进入生产分配算法，只作为阶段 0 研究信号。读取、`lseek`、共享 open-file description、FD 关闭/复用会产生错误正向差值，`pwrite/mmap` 又可能不推进 offset；若未来采用，必须按 `(st_dev, st_ino)` 限定常规 vnode、去重共享 FD、排除异常跳变，并且只能弱调节事件权重，不能充当写入字节或提高证据等级。
5. `deviceWrittenBytes` 不作为强行配平上限，因为缓存、合并、压缩和延迟落盘会使设备与进程口径在同一窗口内天然不一致。卷到物理存储为多对多时只展示“存储集合”；不把 `A(v)` 复制到任一物理设备。

区间先过“采集完整度”，再计算“分卷估算覆盖率”：

1. rusage 累计计数可由缺口前后同一进程会话的单调样本可靠跨越时，将真实起止区间记为一个更粗粒度桶；不得拆分或插值。
2. Extension 断开后进程在缺口内退出、会话身份变化、计数器重置或采样失败且无法跨越时，标为 rusage 不完整。任何不可跨越缺口与所选区间重叠，完整区间的关联量、平均、峰值统一显示“字节不可估算”；高级视图可显示明确标为“仅已观察部分”的数据。
3. 只有 rusage 完整时才定义分卷估算覆盖率：`Σ可估算桶 processWrittenBytes / Σ全部桶 processWrittenBytes`。它只是已有进程写入样本的模型覆盖率，不代表 ES 事件字节覆盖率。分母为 0 时显示“无进程写入样本 / N/A”，不计算 `0/0`。
4. 覆盖率 `≥95%` 时，“关联写入估算”为可估算桶之和，“平均（估算）”除以完整选择时长并包含空闲，“峰值（估算）”取最高可估算采样区间平均速率并动态标注 1/2/10/60 秒粒度，同时展示模型未分配量；低于 95% 时三项统一显示“字节不可估算”。

图表和导出携带 estimator version、真实采样起止、rusage 完整度、分卷估算覆盖率、定稿状态、模型未分配量与证据状态。阶段 0 若多卷估算达不到第 7.3 节门槛，则多卷场景只显示进程总写入、目标卷集合和模型未分配量。

### 4.3 身份与映射

- 进程会话键使用 `audit token + 启动时间`；PID 只用于显示和短期查找，避免 PID 复用造成串线。基础模式始终显示“当前用户可见进程”覆盖标签。
- 应用聚合优先使用代码签名 team ID、signing ID 和 bundle ID；无法识别时退回可执行文件身份。
- 卷身份优先使用 volume UUID。IORegistry entry ID 与 BSD 名称只作为会话标识；跨重启采用最佳努力硬件指纹，无法证明同一设备时不自动合并历史。
- APFS、Fusion Drive、RAID、磁盘镜像与网络卷使用卷↔块设备的多对多拓扑。网络卷只显示文件活动与服务器卷身份，不显示本地物理设备吞吐。卷级写入仅表示关联活动，不把共享物理计数器伪装为独立卷的精确字节数。
- 多用户时系统扩展只向当前控制台且已完成授权的用户 Agent 提供该用户可见的完整路径；其他 UID 的系统级进程统计仅以脱敏身份聚合。快速用户切换时先关闭旧连接再切换数据所有者，禁止向多个用户广播全系统路径。
- 缓存、内存映射写、文件系统合并与延迟落盘会造成时间偏移；归因窗口应允许 2 至 5 秒可配置容差。

### 4.4 性能与可靠性预算

以下是阶段 0 使用 Instruments、`powermetrics` 和内部压测工具校准的首版门槛。CPU 百分比统一按 Activity Monitor 口径，即一个逻辑核满载为 `100%`，Agent 与 Extension 进程相加；采样间隔 1 秒。Apple Silicon 基准机固定为 2020 MacBook Air M1/8 GB，Intel 为 2020 13 英寸 MacBook Pro 四核 i5/8 GB，均接电、关闭低电量模式、室温 `22±2°C`，先预热 10 分钟。最低支持 macOS 与当前最新 macOS 的具体 build、工具版本和后台进程清单写入报告；每场景重复 3 次，报告各轮及最差 P95/P99，Intel CPU 门槛放宽 1.5 倍。性能协议在 RC 前冻结版本，任何门槛或环境变更必须有架构决策记录。

| 场景 | 事件输入与时长 | CPU（Agent+Extension） | 内存与丢弃 |
| --- | --- | --- | --- |
| 空闲 | `<50` 事件/s，30 分钟 | 平均 `<1%`，P95 `<2%` | 稳态 `<120 MB`，本地丢弃 `0` |
| 常规 | `500` 事件/s、500 进程、3 卷，30 分钟 | 平均 `<3%`，P95 `<6%` | 稳态 `<140 MB`，本地丢弃 `0` |
| 持续高负载 | `5,000` 事件/s、1,500 进程、8 卷，30 分钟 | 平均 `<7%`，P95 `<12%` | 峰值 `<180 MB`，本地丢弃 `0` |
| 事件风暴 | `20,000` 事件/s，10 分钟 | 平均 `<12%`，P95 `<20%` | 峰值 `<220 MB`，本地丢弃 `≤0.1%` 且必须显式降级 |

- UI 独立稳态内存 `<180 MB`、峰值 `<250 MB`；常规负载下输入响应 P95 `<100 ms`，XPC 快照端到端 P95 `<500 ms`，ES 回调入队 P99 `<5 ms`。
- 本地环形队列初始容量 100,000 事件。超限顺序为：提高同类事件聚合强度 → 禁用原始事件视图 → 丢弃最低证据强度事件；连续 30 秒低于容量 50% 才恢复。任何丢弃覆盖当前窗口时显示“证据不完整”。
- ES 的 `seq_num/global_seq_num` 间隙单独记为“ES 序号缺口，原因未知”；本地队列才记录已知丢弃原因与数量。二者不得混称，任一序号缺口都使对应窗口证据状态降级。
- 默认设备/进程样本周期为 1 秒，UI 更新上限为 2 Hz，写库采用批量事务。24 小时库体积目标 `<500 MB`，7 天 `<750 MB`，30 天 `<2 GB`；FindDiskKiller 自身平均写入 `<50 KB/s`，保留清理 P95 `<5 s`。
- 睡眠、唤醒、快速用户切换、磁盘热插拔、卷卸载、系统扩展重启都必须产生明确状态转移，不补造缺失数据。
- FindDiskKiller 自身数据库与日志写入默认从归因榜单排除，但在诊断模式中可见，以避免“监控软件成为首要写盘者”的困惑。

### 4.5 本地存储

普通历史使用 SQLite WAL，数据契约如下：

| 数据层 | 介质与默认保留 | 内容与路径策略 |
| --- | --- | --- |
| 实时视图 | Agent 内存环形缓冲 15 分钟 | 实际 1/2 秒样本桶与合并活动；完整路径最多驻留 15 分钟，不进入日志或崩溃报告 |
| 普通历史 | SQLite，24 小时 | 10 秒桶、异常和目录标签；不保存完整路径，UI 显示“路径未保留”而不是“无活动” |
| 长期历史 | SQLite，可选 7 或 30 天 | 1 分钟桶、规则记录和脱敏身份，不保存完整路径 |
| 异常基线 | 独立摘要表，35 天 | 主体类型、稳定应用/设备身份、读写方向、同类时段分位数、MAD 与样本数；不含路径或原始事件 |
| 诊断记录 | 独立会话文件，默认 30 分钟、最长 2 小时或 2 GB | 用户逐次同意后保存完整路径；显示计时、预计空间与自动停止，可随时结束、脱敏导出或删除 |

完整路径只在系统扩展事件复制、受校验的 XPC 消息、Agent 实时内存和当前 UI 选中内容中短暂出现；默认不进入普通 SQLite、日志和崩溃报告。需要跨桶关联时使用 keyed HMAC，密钥保存在当前用户 Keychain；“重置路径身份”会删除密钥并使旧伪名不可关联。诊断会话文件位于应用容器、权限 `0600`，关闭“诊断记录完整路径”时提示并逻辑删除既有会话；同时提供“立即清除历史”。由于 SSD 无法保证物理安全擦除，文案不得承诺不可恢复擦除。

### 4.6 安全边界

- 系统扩展只观察，不拦截文件访问；最小化订阅事件类型。
- 每条 XPC 连接使用 audit token 与 SecCode designated requirement 校验 Team ID、签名标识和预期 entitlement，并限制消息尺寸、速率与协议版本；不接受任意本地客户端连接。
- 不通过自制密码框索取管理员密码；安装、系统扩展批准和隐私授权全部走 macOS 系统界面。
- 日志禁止记录完整命令行、环境变量和默认完整路径；诊断包生成前提供内容预览。
- 产品自身唯一主动联网能力是基于 Sparkle 2（固定并审计版本）的可关闭自动更新，固定访问 `https://updates.find-disk-killer.app/`；网络性能监控只读取本机系统累计计数，不建立外部连接。应用不发送设备 ID、使用数据、路径或事件，只包含常规 HTTPS 请求信息和更新所需的当前版本/系统版本。更新清单与包同时校验 Sparkle EdDSA 签名、Developer ID 和版本单调性，禁止静默降级。
- 分批比例来自签名 feed；本机用 Keychain 安装随机值与 release version 做 HMAC 后取模，决定是否进入 10% cohort，该值不上传。48 小时仅观察自动化 canary 的签名/公证/启动/升级结果、用户主动提交的诊断和支持事件，不声称有全量安装成功率遥测。任一签名/公证/无法启动/数据损坏问题，或 3 个独立用户报告同一 P1 更新故障，即暂停 feed 放量。
- 安装事务尚未提交时可恢复旧 App。安装后发现回归时不自动降级系统扩展：先停止放量，优先前向修复；只有旧 App 已验证兼容现有较新扩展协议时才允许回退宿主 App。应用不包含遥测；更新域名未就绪时以手动更新发布，不临时扩大联网范围。

### 4.7 签名、安装与卸载

- 宿主 App 包含 `com.apple.developer.system-extension.install`；ES 扩展包含 Apple 批准的 `com.apple.developer.endpoint-security.client` Developer ID provisioning profile。
- 扩展嵌入 `Contents/Library/SystemExtensions`，宿主与扩展使用同一 Team ID，启用 Hardened Runtime 与 secure timestamp，并按嵌套代码顺序签名、公证和 stapling。
- 宿主 `Info.plist` 提供 `NSSystemExtensionUsageDescription`，扩展明确配置 `NSEndpointSecurityMachServiceName`。
- 升级验证 bundle/version 迁移和扩展替换；禁止自动降级。卸载由应用内流程发起 `OSSystemExtensionRequest.deactivationRequest`，同时注销 Agent。仅将 App 拖入废纸篓时提示系统扩展可能仍待系统清理，不声称已经完整卸载。

## 5. 异常分析与诊断

### 5.1 异常判定

- 某设备写入速率持续高于用户阈值 60 秒。
- 某进程写入速率超过过去 7 个同类时段中位数与 MAD 形成的本地基线；基线样本不足时不默认启用。
- 监控数据因扩展断开或事件丢弃而不完整。

冷启动采用“均衡”绝对阈值：设备写入 `≥20 MB/s` 持续 2 分钟，或单进程写入 `≥5 MB/s` 持续 5 分钟；同时显示按当前速率折算的 24 小时写入量。电池低于 20% 时不运行高频基线计算。数据不完整时暂停进程归因判定，并在应用内标明“监控能力下降”。同一问题持续存在时只更新现有状态，不发送系统通知、不自动弹出窗口；用户主动打开菜单栏面板或主窗口后，可从“卷/存储 + 相关进程证据 + 持续时间”进入冻结的历史窗口。

### 5.2 诊断导出

诊断包采用版本化结构，包含应用版本、macOS 版本、设备拓扑、权限状态、指标桶、规则事件和丢弃计数。完整路径、命令行和用户名默认排除。导出界面先展示预计大小和隐私字段，再生成压缩包。CSV 对以 `= + - @` 开头的单元格进行防公式注入转义；恶意文件名不得改变目录结构。临时文件使用 `0600` 权限和随机名称，取消或失败后立即逻辑删除并清理空目录。

## 6. 交付计划

## 7. 测试策略

### 7.1 自动化测试

- 时间桶、计数器差值、回绕与睡眠间隔的单元测试。
- PID 复用、进程聚合、多对多卷映射、关联字节守恒和证据状态的确定性测试。
- 应用/设备基线键、读写方向、设备更换和跨重启身份无法确认时回到“学习中”的确定性测试。
- 两条 XPC 协议的版本兼容、签名/audit token 拒绝、异常输入、消息限流、连接中断和扩展重启测试。
- SQLite WAL 崩溃恢复、迁移失败、损坏、磁盘满、清理中断、脱敏和导出快照测试。
- CSV 注入、路径穿越式文件名、临时文件权限与取消导出清理测试。
- SwiftUI 浅色/深色、降低透明度、增强对比度、长名称、大字号和窄窗口截图；图表无障碍描述和等价表格快照测试。

### 7.2 受控场景测试

- 单进程向单卷连续写入，验证实测进程总量、正确卷关联、估算平均与带实际粒度的估算峰值。
- 单进程按已知比例同时写两个卷，验证分配误差或按门槛自动退回“不显示分卷字节”。
- 多进程写同一 APFS 容器，验证共享设备总量与卷级活动的口径提示。
- 大文件顺序写、高频小文件、`pwrite`、`mmap`、缓存后延迟落盘、短命命令行进程，并分别验证 WRITE/CLOSE/可写映射/元数据事件分类。
- 外置盘热拔插、卷强制卸载、系统睡眠、扩展被终止、FDA 被撤销。
- 设备更换、同型号热插拔与跨重启硬件身份不确定时验证不串用设备读写基线。
- Extension 断开后分别验证：同一会话累计计数可跨越时形成粗粒度桶；进程在缺口内退出或会话变化时完整区间三项不可估算。
- `path_truncated`、ES 序号缺口与本地队列丢弃分别显示正确语义。
- 首装、覆盖升级、系统升级、扩展更新失败、禁止降级、卸载重装；系统时钟/时区变化和快速用户切换。
- 支持矩阵覆盖每个 macOS 大版本、Apple Silicon/Intel、内置/外置、APFS 加密/大小写敏感、磁盘镜像和网络卷。网络卷预期为“仅文件活动，无本地物理吞吐”。
- 事件风暴下验证 UI 可响应、降级顺序正确、丢弃可见、内存有界。

### 7.3 数据质量门槛

阶段 0 维护版本化基准规范，固定负载工具、硬件、系统版本、10 秒预热/冷却和窗口算法：

- 设备吞吐：使用 `F_NOCACHE + fsync` 的受控 30 秒顺序写夹具，对照已提交字节、`iostat` 与设备计数器；静止测试卷上的累计差异 `≤5%` 或 `≤8 MB`（取较大者）。
- CPU：受控单线程和多线程负载各运行 60 秒，对照 Activity Monitor 与 Instruments；整机 CPU 绝对误差 P95 `≤3` 个百分点，应用 CPU 按“一个逻辑核为 100%”口径的绝对误差 P95 `≤5` 个百分点，计数器回绕或采样缺口不得产生尖峰。
- 网络：在 Wi-Fi、有线、VPN 切换和接口热插拔场景运行固定字节的本地 TCP 夹具；物理外部接口累计量相对夹具误差 `≤5%` 或 `≤1 MB`（取较大者），应用网络相对 `nettop` 同窗口误差 `≤5%`。接口上线不得带入历史累计量，采样失败和恢复的首个样本必须显示缺口且不得产生尖峰。
- `nettop` 兼容矩阵覆盖最低支持版本及当前最新 macOS：正常输出、空结果、非零退出、超时、进程退出、PID 复用、连接关闭和字段变化全部有夹具；任一失败都不得阻塞磁盘/CPU 采样超过 2 秒，也不得把不可用显示为 0。
- 单进程单卷：正确目标卷 precision `100%`、recall `≥99%`；关联写入估算相对进程实测量误差 `≤10%`，模型未分配量 `<5%`。
- 单进程双卷：目标磁盘 precision `≥99%`、recall `≥95%`；每卷估算中位绝对百分比误差 `≤20%`、P95 `≤35%`。达不到即执行第 4.2.1 节的 UI 降级，不带数值发布。
- 受控场景的未知卷/未知进程事件比例分别 `<1%`；持续高负载本地丢弃为 `0`，事件风暴按第 4.4 节门槛。短命进程身份捕获率 `≥90%`，无法获得字节时必须标为“活动已观察、字节未知”。
- 注入 ES 序号缺口、未知确认目标或本地丢弃时，受影响桶的全部进程写入进入模型未分配量；选择区间可估算覆盖率低于 95% 时，关联量、平均、峰值三项同时降级。
- rusage 可跨越缺口必须保持同一进程会话、计数单调且真实起止时间完整；不可跨越缺口重叠选区时采集完整度 Gate 必须优先阻断 95% 公式。分母为 0 时显示 N/A。
- 异常状态在持续条件满足后 2 秒内反映到已打开的主窗口或菜单栏面板；状态更新保持稳定，不闪烁；24 小时基准回放误报 `<1` 次。

### 7.4 用户体验验收

- 至少 12 名目标用户在无引导测试中，90% 能在 30 秒内从指定异常进入时间段查询，并正确说出进程、目标卷/存储集合、关联写入估算、估算平均和估算峰值；任务从异常卡片出现开始，以正确打开结果行为结束。
- 至少 8 名非内核/存储背景用户中，80% 能正确区分进程实测写入、分卷关联估算和设备物理写入，不把它们理解为可精确对账。
- 首次启动基础模式可识别写入最高设备；基础模式进程榜不会被误解为已按磁盘归因。
- 用户能完成启用完整模式、从异常状态回看冻结历史、权限中途撤销后恢复，以及外置盘拔出后继续查看会话。
- 权限被拒绝后仍可继续使用，并清楚知道缺失的能力。
- 任一异常指标可在两次点击内进入对应进程或活动证据。
- 所有估算量及派生速率均带 `约`/估算标记、依据和模型未分配量，完整路径未保留时不被误解为“无活动”。
- 长进程名、长卷名使用专业截断并可访问全名；大字号和最小窗口下无内容遮挡，可通过键盘与 VoiceOver 完成主要流程。

| 用户把估算当成精确落盘 | 中/高 | 产品设计 | 可用性测试理解率低于 80% | 保留 `约`、三量核对和依据；阻断发布直至文案复测 |
| 高频事件导致 CPU、内存或事件丢弃 | 中/高 | 平台负责人 | 触发 4.4 任一预算 | 分级聚合和关闭原始视图；仍超限则降采样并显示缺口 |
| FDA/扩展流程导致启用失败 | 中/中 | macOS 负责人 | 完整模式完成率低于 85% | 权限状态机、自动复检、诊断导出；基础模式不中断 |
| 短命进程被轮询漏掉 | 高/中 | 采集负责人 | 身份捕获率低于 90% | ES 生命周期补足；字节未知时只报告已观察活动 |
| 品牌图标许可或身份误配 | 低/高 | 发布/法务 | registry 许可变化、商标投诉或识别冲突 | 固定版本、逐项审计、快速撤下资产、退回本地图标 |
| 数据库损坏或磁盘写满 | 低/高 | 存储负责人 | WAL 恢复失败或剩余空间低于上限 | 停止历史写入而保持实时内存监控；提示清理并保留只读诊断 |

## 9. 发布范围与非目标

### 基础版 GA 必须包含

- 菜单栏实时状态、持续读写异常、设备与卷层级、总览趋势。
- 当前用户可见的进程 I/O 排名、进程详情和退出后会话记录，并明确未按磁盘归属。
- 全局实时/历史时间上下文、24 小时普通历史、停止采集与脱敏导出。
- 睡眠唤醒、热插拔、数据库恢复与数据缺口的可靠处理。

### 完整模式 GA 额外包含

- 时间段“进程 → 卷/存储集合”的关联写入估算、估算区间平均、带实际粒度的估算峰值、模型未分配量与文件活动证据。
- ES 权限状态机、多用户隔离、活动时间线、诊断记录和扩展异常降级。
- Codex、Claude/Claude Code 等首批 AI 工具的身份聚合与已审计图标回退；本地 `.app` 图标始终优先。
- 达到第 7.3 和 7.4 节门槛；若多磁盘字节估算不达标，按既定降级形态发布。

### 首版不包含

- 文件访问阻断、进程终止或自动清理文件。
- 云端账号、远程主机监控、团队协作与跨设备同步。
- 对 SSD 寿命、SMART、温度、队列深度作跨设备统一承诺。
- 将分卷关联写入估算用于计费、审计或取证，或声称其与物理设备字节可精确对账。
- 内核扩展或依赖私有、易变接口的正式实现。
