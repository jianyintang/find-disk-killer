# Now 常态 CPU 优化（2026-09-29）

用户反馈 Now 页常态超过 20% CPU。本轮从实际 Release 进程采样，修改渲染和观察边界，再以真实应用进行对比；没有降低采样频率或切换到低动效来制造收益。

## 根因与落地

- 磁盘趋势原先让整个 Swift Charts 数据域和每个 mark 在采样后一起动画，并使用 `drawingGroup`。现在坐标轴、网格、阈值、悬停交互仍由 Charts 管理，数据曲线和填充采用缓存的 `CGPath` / `CAShapeLayer`，每个样本更新一次路径，只让合成器执行 0.36 秒平移。
- CPU 卡片原先为每核、每个分段维护 SwiftUI 节点和动画。现在静态网格合为一个 shape layer，各分段使用原生图层缩放，从 presentation layer 的当前高度平滑过渡，保留 0.48 秒动效、阈值颜色和原有视觉尺寸。
- 卷概要和趋势图原先通过 `ViewThatFits` 创建两套完整宽窄布局。现在一个 `Layout` 在两种宽度下明确放置同一份卷概要、分隔线和图表，跨断点保留图表状态。
- Overview 根视图只管理交互状态。标题、六张指标卡、磁盘活动和应用表格分别观察自己的数据，避免进程汇总、容量等发布反复使整个仪表树失效。
- `DataValue` 移除两份数字候选树，改为一份数字随可用空间连续缩放，保留 `numericText`、首基线和单位完整显示。

原生渲染遵循减少动态效果、低动效和窗口遮挡状态。显示器缩放、明暗主题变化会刷新图层。悬停查看数值时立即停止曲线平移，保证标记和数据对齐；滚动边界保留一个真实前驱样本用于裁剪，不能跨缺失数据或分段连接。无障碍图表描述仍提供完整的真实样本序列，不把建立坐标范围的两个透明 mark 当作业务数据。

## 实际 CPU 测量

环境：Apple M5 Pro，18 逻辑核，64 GiB，macOS 26.5.2。SwiftPM Release；1 秒采样、完整动效、Now 默认磁盘视图、1 分钟范围、1174 × 879 pt 窗口。约 1,000 个系统进程。CPU 使用 macOS `top` 进程口径，100% 代表一个逻辑核。

旧版启动约 78 秒后采样 15 个有效读数；最终版运行约 5.8 分钟后复测 12 个有效读数。两轮均明确将 Now 切到前台，确认测量前后窗口都在屏幕上、滚动位置为顶部。`top` 间隔 2 秒，丢弃初始化读数；测量期间没有构建或测试。

| 指标 | 旧版前台 | 最终版前台 |
| --- | ---: | ---: |
| FindDiskKiller 平均 CPU | 22.31% | 13.05% |
| FindDiskKiller 中位 CPU | 22.5% | 12.45% |
| FindDiskKiller 样本范围 | 18.9–24.4% | 9.5–18.3% |
| WindowServer 平均 CPU | 86.15% | 52.03% |

这说明最终版在本机完整前台复测中明显低于原先的常态占用。两轮启动时长、后台负载及显示器不同（同为 2× Retina；旧版 Studio Display，新版 LG UltraFine），因此不把二者差值宣传为严格固定场景下的提速百分比。一次启动时长匹配的新版本测得 13.21%，但结束时窗口已离屏，已明确剔除其对照资格。前后窗口状态见[记录](now-cpu-2026-09-29/window-state.json)。

桌面上仍运行用户的其他应用，采样的数据与系统负载不是固定回放。因此这些是本机实测结果，不是所有机器和所有交互的 CPU 上限。WindowServer 还服务其他应用，不能把它的全部变化归因于本次修改。

早期观察到旧进程长时间运行时平均 28.43%，新启动旧版为 17.79%；二者不可互作优化对照。分阶段结果为：磁盘原生曲线 15.52%，再改 CPU 网格 12.28%，再隔离标题／应用区 9.77%。这些窗口没有完整的前台状态记录，只作为定位过程。中间版本运行 5 分钟的一次窗口为 16.58%，另一次滚动后的窗口为 13.41%；期间用户改变了窗口／滚动状态，不能据此断言历史增长或应用列表是根因，也不能声称长时间运行一直保持个位数。

[逐样本数据](now-cpu-2026-09-29/cpu-samples.json)保留中间阶段与最终测量。复测可使用：

```sh
top -pid <FindDiskKiller_PID> -l 16 -s 2 -stats pid,cpu,time,threads,mem
sample <FindDiskKiller_PID> 8 2 -file /tmp/finddiskkiller-now.sample.txt
```

比较时须匹配 Release 构建、启动时长、前台／遮挡状态、窗口尺寸、滚动位置、时间范围、采样间隔和动效档位。`sample` 用于定位调用栈；其等待栈和包含子节点的计数不能直接相加当作 CPU 消耗。

## 验证

- Release 编译通过；图表、窗口统计、监控、本地化相关的 82 项测试通过。
- 新增数据分段与边界前驱测试，覆盖缺口、非有限值、重复／倒序时间戳及跨分段不连线。
- 视觉检查覆盖 1120 pt 明暗、720 pt 暗色、805 pt 断点附近浅色布局，确认每个布局只有一个原生趋势图和一个 CPU 网格；没有重叠或新插入的活动区块。
- 独立动画探针验证平移过程中的 presentation transform、左边界真实前驱、CPU 分段动画和低动效切换时清除动画。测试窗口在 XCTest 中被系统标记为遮挡，因此该探针显式模拟可见窗口状态；它不是 FPS、实际 VoiceOver 或整机 GPU 测试。
- 原生组件继续隐藏装饰图层，使用原有卡片概要和自定义真实数据 AXChartDescriptor。未开展完整 VoiceOver 朗读／音频图表验收。
- 用 raw SwiftPM 可执行文件运行，不生成额外 `.app`；测试探针已退出、临时测试源已移出测试目录。Launch Services 查询只返回 `/Applications/FindDiskKiller.app`，未改动安装版或发布产物。

## 范围与下一步判断

本轮原生曲线只替换磁盘趋势图；切换到大幅 CPU、网络或内存趋势图时仍使用原来的 Swift Charts 实现。进程采样、历史保存和统计口径未改动。其余小图不应仅因出现 Shape 就全面重写：后续采样中 Charts 只占很少调用栈，而主要剩余工作是 SwiftUI 更新与自适应布局。

如果还需要进一步降低持续占用，应先对用户实际停留的视图、所选指标、采样间隔进行前台长时间采样，再决定复用原生绘图层或优化剩余布局。当前证据不足以支持把整个列表重写成 NSTableView 或把整页迁移到 Metal。空间扫描的紧凑 inode 账本原型属于另一个独立议题，不能把其微基准收益算到 Now CPU 改进中。
