# 空间地图布局与性能审计（2026-09-28）

这轮修复保留精确物理占用统计、文字／按钮流光和数字滚动，消除了重复布局及扫描器的一处增长数组复制。最大的后续机会是紧凑物理账本和增量合并；原型已有对比数据，但尚未替换生产账本。本文不将局部基准等同于整机提速。

## 已落地

| 改动 | 作用与边界 |
| --- | --- |
| 空间地图按实际宽度只构造一个布局分支 | 移除同时持有宽窄页面、只放置其中一份的自定义 Layout。未放置子视图仍可能绘制，这正是此前内容重叠的原因。标题 Layout 现在测量并放置全部三个真实子项。 |
| 表头与行共用列宽／断点 | 避免表头已切换而行仍保留另一种布局；窄布局补足行距，双卡片与主要卡片行保留 180 pt 最小宽度，使容量单位完整显示。 |
| 轻量 dashboard 数据 | Dashboard 每次更新只构造一次来源／卷投影；仅传递标识、标题、图标、活动状态和容量，不再为卡片生成完整详情 presentation 或携带资源树。尚未改为每来源独立观察对象。 |
| Agent 累积改用 scoped `inout` | 一次借用 family、再借用 node，在原缓冲区追加清理条目，避免每次取出／写回值类型造成增长数组复制；保留计数、分类、缺失 metadata 的回退和清理资格判定。 |
| 每来源只规范化每个根路径一次 | 原先每个 root worker 都重新解析所有根，文件系统符号链接解析由平方次降为线性次；字符串祖先比较仍是平方级。遍历与排除规则使用同一规范化目标，避免排队期间符号链接换目标导致漏算。 |
| 磁盘趋势图常量翻译前移 | 时间／读／写／系列等六个标签每次 body 更新只解析一次，图表每个点复用字符串；不是永久静态缓存，语言切换仍生效。 |
| 停止首次联合分析后保持可操作状态 | 记录本轮自动分析已经开始，停止后不再误判为等待自动扫描。保留已完成的空间统计；没有结果时显示可开始分析的页面。即使 Agent 明细未完成，已完成的空间统计也保持可见。离开再进入不自动重启，用户仍可手动重试。 |

动效继续局限于已有文字、按钮与数字，不插入会挤动内容的活动区块。数字采用 SwiftUI numeric content transition，遵循“减少动态效果”。进度数字来自实际扫描回报。

## 对比数据

环境：arm64、macOS 26、Swift 6.3.1、64 GiB RAM。`swiftc -O -whole-module-optimization`；每个样本独立进程，各三次、交替顺序、报告中位数。数组累积验证完整嵌套结构相等；账本原型逐 inode 验证规范化校验和。下列是合成数据结构实验，排除了文件枚举、数据库解析和 UI 渲染。

| 数组累积分布 | 条目数 | 原取出／写回 | 反复字典下标 | 最终 scoped inout |
| --- | ---: | ---: | ---: | ---: |
| 32 families × 4 nodes 均匀分布 | 1,000 | 0.902 ms | 1.507 ms | 0.887 ms |
| 同上 | 8,000 | 5.735 ms | 9.115 ms | 4.109 ms |
| 同上 | 32,000 | 36.589 ms | 35.847 ms | 14.875 ms |
| 8 × 8、90% 集中于单节点 | 1,000 | 2.884 ms | 1.507 ms | 0.931 ms |
| 同上 | 8,000 | 126.319 ms | 8.817 ms | 4.096 ms |
| 同上 | 32,000 | 1,938.160 ms | 33.220 ms | 14.424 ms |

最终实现避免了反复字典下标在部分均匀场景的退步。小规模均匀场景基本持平；32k 均匀场景约 2.46 倍，集中场景约 134 倍。这些倍率仅适用于表中累积函数，不代表扫描或整个应用快了同等倍数。

| 单 claim 账本原型 | 原构建时间 | 紧凑构建时间 | 原进程峰值 RSS | 紧凑进程峰值 RSS |
| --- | ---: | ---: | ---: | ---: |
| 100k 唯一 inode | 14.527 ms | 4.006 ms | 38.33 MiB | 20.06 MiB |
| 1M 唯一 inode | 171.302 ms | 49.673 ms | 274.91 MiB | 104.30 MiB |

两种账本使用相同 Dictionary 容量、完整 `(device, inode)` 键和共享不可变字符串；紧凑版把单 claim 内联，以索引引用不变 metadata，保留精确字节数和 Date。1M 原型构建约快 3.45 倍、峰值 RSS 降低 62.1%。它尚不支持生产中的多 claim 仲裁、跨来源刷新和取消，不能直接接入正式扫描器。

复现（macOS，输出默认写入新建临时目录，不生成 app）：

```sh
python3 scripts/performance/run-storage-benchmarks.py
```

本轮最终复跑的[汇总数据](storage-benchmark-2026-09-28/summary.json)、[环境](storage-benchmark-2026-09-28/environment.json)与[结构相等性结果](storage-benchmark-2026-09-28/verify.jsonl)已入库。脚本输出环境、各次时间／峰值 RSS、相等性检查和汇总 JSON；`--output` 可指定目录。峰值 RSS 是独立基准进程口径，与 Instruments physical footprint 不可混用。

## 深层瓶颈与实施顺序

1. **优先：紧凑物理账本 + 归属反向索引。** 为正确处理跨根硬链接、分卷占用和真实文件数，当前扫描保留逐 inode 明细。session 又保留各来源账本并构造合并字典，新旧代际交叠时形成显著内存压力。建议固定宽度 row，单 claim 内联，多 claim 放辅助表，不变根／分类／卷信息驻留一次；建立 identity → source 索引，只重算受影响的连通来源。不可退回 `du` 根总量而丢失精确去重。预计是本轮最有价值的下一阶段，原型尚需生产等价验证。
2. **共享物理观察流。** Storage Map 和 Agent 扫描同一 AI 根；Agent 后续还需稳定性校验。让两者消费同一轮物理观察结果，保留清理所需的复验，避免重复枚举和 stat。需明确扫描代际、取消与授权边界。
3. **规范化缓存和后台快照构建。** Agent cache 顶层 families 与 providerDatasets 重复编码同一批实体，本机缓存约 79 MiB。新缓存格式每个实体存一次，重建小索引；大型快照合并与释放需按 trace 再确认主线程占用，再迁移到后台所有权。
4. **缩小实时 UI 更新范围。** 当前已减少数据投影，下一步可按来源隔离观察状态，保留汇总头独立更新；Overview 也需拆分真正子 View。先记录实际 body／layout 次数，避免靠延长进度节流掩盖问题。
5. **有条件替换图表绘制层。** 若去除重复布局和每点翻译后 trace 仍以 Swift Charts 为主，可将曲线路径移入 layer-backed NSView + CAShapeLayer，坐标轴、tooltip、无障碍仍保留 SwiftUI。先试一个磁盘图验证收益；目前没有证据支持整页 Metal 重写。

当前已经有后台扫描、有限并发、每来源约一秒进度节流、静态玻璃材质；重复这些通用建议不能解释或解决主要剩余开销。

- Debug／Release 构建成功，`git diff --check` 通过。
- 244 项相关测试通过，覆盖空间地图、Agent、统计与本地化；新增“排队期间根符号链接换目标”及“停止首次联合分析、重新进入与手动重试”的行为回归。后者同时覆盖尚无结果与空间统计完成但 Agent 仍在扫描两种状态。

- Release 实际窗口截图再次确认无重叠；进程外 AX 检查中主分析按钮与清理按钮各一个。进程内 SwiftUI accessibility probe 没有导出子节点，不能用其零计数证明无重复控件。停止状态的最终修复由两种真实异步模型场景回归验证。
- 当前 Release 已启动在空间地图；Spotlight 与 NSWorkspace 注册查询均仅返回 `/Applications/FindDiskKiller.app`。使用 SwiftPM 可执行文件，没有生成临时 app bundle／DerivedData 或挂载测试磁盘映像。
- 构建仍有既存的 ChartAnimationGate MainActor 隔离警告；本轮未更改该门控代码。
- 原 Debug 活跃扫描曾观察到约 1.9 GiB footprint、约 2.9 GiB 峰值，主线程包含 SwiftUI／AttributeGraph／layout，工作线程包含 Agent 元数据／物理账本／累积与 ARC。重新打开后的 idle 内存不构成有效对照。
- 本轮最终 Release 的一次三秒采样记录约 1.5 GiB footprint、约 2.2 GiB 进程峰值，说明内存压力仍在；采样阶段和构建模式与旧 Debug 不同，不计算前后降幅。
- 尚无同一完整数据集的 Release 整机前后对照，不能声称所有卡顿或内存问题已经解决。下一阶段必须同时测扫描耗时、主线程 p95/p99 停顿、动效／滚动帧间隔、扫描峰值／结束后 footprint、取消退出延迟，并验证硬链接、重叠根、卷归属、权限错误、文件变化与清理资格完全等价。
